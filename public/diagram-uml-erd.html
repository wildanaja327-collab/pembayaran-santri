Dokumentasi Perancangan Sistem Informasi

Sistem Informasi Pembayaran Syahriyah Santri (E-Syahriyah)

Pondok Pesantren Darul Muttaqin — Terintegrasi Midtrans Payment Gateway & Fonnte WhatsApp Gateway
Framework: Laravel 11.x (PHP 8.2, MVC)
Database: MySQL Relational DB (11 Tabel)
Standar Notasi: UML 2.5 & Crow's Foot ERD
BAGIAN 1 — FLOWCHART SISTEM
1.1. Flowchart Alur Utama Sistem Informasi Pembayaran Santri (End-to-End)
Menggambarkan siklus hidup tagihan mulai dari konfigurasi data master, penerbitan tagihan, pembayaran online/tunai, pengajuan penundaan, hingga pelaporan.
Keterangan Alur: Sistem mendukung 3 jalur penyelesaian tagihan secara terpadu: (1) Self-Service Payment Gateway melalui Midtrans QRIS/VA (penuh maupun cicilan), (2) Kasir Tunai oleh Bendahara, serta (3) Mekanisme Pengajuan Penundaan & Alasan Tunggakan dua arah antara Wali Santri dan Bendahara.

SPESIFIKASI SKEMA DATABASE
2.2. Kamus Data & Relasi Kunci Asing (Foreign Keys)
No Nama Tabel Primary Key Foreign Key / Relasi Fungsi Utama dalam Sistem E-Syahriyah
1 users PK id_user UK username Menyimpan akun pengguna multi-role (admin, bendahara, wali_santri).
2 program PK id_program - Data master program unggulan pesantren (Tahfidz, Kitab Kuning, Bahasa, Sains).
3 tahun_ajaran PK id_tahun_ajaran - Data master periode tahun ajaran dan semester aktif (Ganjil/Genap).
4 santri PK nis FK id_program → program
FK id_wali → users		 Biodata santri SMP/SMA, status aktif, serta tautan ke akun Wali Santri.
5 jenis_tagihan PK id_jenis_tagihan - Master komponen biaya pendidikan (Syahriah Bulanan, Uang Pangkal, Daftar Ulang, dll.).
6 tagihan PK id_tagihan FK nis → santri
FK id_jenis_tagihan → jenis_tagihan		 Kewajiban bayar santri, progres cicilan, serta alasan tunggakan, tanggal janji bayar, & tanggapan bendahara.
7 pembayaran PK id_pembayaran FK id_tagihan → tagihan
FK verified_by → users		 Transaksi pembayaran via Midtrans Gateway (QRIS/VA) maupun Kasir Tunai Bendahara.
8 kwitansi PK id_kwitansi FK/UK id_pembayaran → pembayaran Bukti pembayaran sah berformat nomor resmi (KWT/YYYYMM/XXXX).
9 notifikasi_wa PK id_notifikasi FK nis → santri Log riwayat pengiriman pesan otomatis WhatsApp melalui API Fonnte.
10 pengaturan PK setting_key - Penyimpanan dinamis kredensial Midtrans, token Fonnte WA, dan profil pondok.
11 activity_logs PK id FK user_id → users Rekam jejak audit keamanan sistem (login, buat tagihan, bayar, ajukan penundaan).

5.1. Sequence Diagram: Pembayaran Online Midtrans Snap, Webhook & Notifikasi WhatsApp
Interaksi objek secara kronologis antara Aktor Wali Santri, Controller, Service, Database, Midtrans API, dan Fonnte API. 
sequenceDiagram
    autonumber
    actor Wali as Wali Santri
    participant View as View: dashboard / show.blade.php
    participant PC as PembayaranController
    participant MS as MidtransService
    participant Midtrans as Midtrans Snap API
    participant WC as WebhookController
    participant DB as Models: Tagihan, Pembayaran, Kwitansi
    participant WA as WhatsAppService (Fonnte)

    Wali->>View: Klik Bayar dan Pilih Nominal (Penuh / Cicilan)
    View->>PC: POST /wali/tagihan/{id}/pay (nominal_bayar)
    PC->>DB: findOrFail(id_tagihan) dan Validasi Sisa Tagihan
    PC->>DB: Pembayaran::create(order_id, jumlah_bayar, status='pending')
    PC->>MS: createSnapToken(pembayaran, tagihan, santri)
    MS->>Midtrans: Request Snap Token (Server Key Auth)
    Midtrans-->>MS: Return snap_token
    MS-->>PC: Return snap_token
    PC-->>View: JSON { snap_token, id_pembayaran }
    View->>Midtrans: window.snap.pay(snap_token)
    Wali->>Midtrans: Bayar via QRIS / Virtual Account Bank
    Midtrans->>WC: POST /midtrans/webhook (JSON Payload + signature_key)
    WC->>WC: Validasi SHA-512 Signature Key
    WC->>DB: Update Pembayaran (status_transaksi = 'settlement')
    WC->>DB: Update Tagihan (total_terbayar, sisa_tagihan, status = 'lunas'/'dicicil')
    WC->>DB: Kwitansi::firstOrCreate(no_kwitansi = 'KWT/YYYYMM/XXXX')
    WC->>WA: sendPaymentConfirmation(pembayaran)
    WA-->>Wali: Pesan WhatsApp Bukti Lunas + Link Cetak Kwitansi
    WC-->>Midtrans: HTTP 200 OK
